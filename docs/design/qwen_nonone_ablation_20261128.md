# Qwen3.8-27B 去掉 none 选项的消融（2026-11-28）

最终 260 题里，Qwen3.8-27B（11-26 MacBook 重跑）有 75 题答 `{"type": "none"}`，按规则全记 0 分。这次把这 75 题用**去掉 none 选项**的提示重跑一遍，看 Qwen 被逼着作答时能答对多少。这是消融实验，**不替换主表**；主表仍是 `eval_final260_results_20261126.md` 里的 Qwen 0.162。

运行设置见 `model_run_settings_20261119.md` 的 “2026-11-28 消融” 一节：与 11-26 MacBook 重跑完全相同（同一 revision b935172、mlx-vlm 0.8.0、temperature 0、max_tokens 2048、不思考、原分辨率），只改了提示。

## 提示改动

新版本 `grounding-v2-nonone-20261128`（`code/prompt.py` 的 `USER_TEMPLATE_V2_NONONE`）。与 `grounding-v2-20261119` 相比，user 提示只删掉最后一行，其余逐字相同（system 提示、原文、问题、图片都不变；37 道改问法的题用改后的问法）：

```diff
 Reply with exactly one JSON object and nothing else, in one of these forms:
 - an area or a place: {"type": "box", "bbox": [x1, y1, x2, y2]}  (axis-aligned box; top-left then bottom-right corner)
 - a route, road, street, boundary or line of troops: {"type": "line", "points": [[x, y], [x, y], ...]}  (at least 2 points, in order along the line)
-- the place is not shown on this map: {"type": "none"}
```

“in one of these forms” 保留不改（两种形式仍是 “these forms”）。

## 结论

1. **75 题里大约三分之一到一半其实能找到大致位置。** 去掉 none 后 75 题全部作答（74 题格式合规，1 题自创了 `{"type": "point", ...}`，按规则记 0）。平均 IoU 0.133 [0.088, 0.183]；hit@0.5 9 题（12.0%）；中心落在金标区域内 19 题（25.3%）；中心距离在 5% 对角线以内 33 题（44.0%）；IoU > 0 的 34 题。原来这 75 题全记 0。
2. **这 75 题对 Qwen 来说确实偏难，但不是“地图上没有”。** Qwen 在其余 185 题上 IoU 0.228、中心命中 41.1%，这 75 题只有 0.133 和 25.3%。闭源模型在这 75 题上也低一些（Sol 0.378 对其余 0.478，Claude 0.332 对 0.422，Gemini 0.445 对 0.494），但下降幅度小得多。所以 Qwen 答 none 多半是“没把握”，而不是题目本身无解；所有题的答案在图上都存在。
3. **替换进 260 题后 Qwen 的整体指标明显上升，但与闭源模型的差距不变。** IoU 0.162 → 0.200（+0.038，95% CI [0.024, 0.054]），hit@0.5 0.119 → 0.154，中心命中 0.292 → 0.365。闭源三家仍在 0.40–0.48，排名不变。
4. **难度三档的单调下降在去掉 none 后更清楚。** 75 题按难度：第 1 档 32 题 IoU 0.211、第 2 档 21 题 0.087、第 3 档 22 题 0.065；中心命中 43.8% / 19.0% / 4.5%。替换后的 260 题 IoU 0.254 / 0.172 / 0.125（KW p = 0.0006，JT p = 0.0002），比原来的 0.204 / 0.136 / 0.107（KW p = 0.008，JT p = 0.0005）更显著。原来的 none 并不集中在难题上（32 / 21 / 22，占各档 24% / 41% / 29%），去掉 none 后难题上猜得差，简单题上猜得较好，梯度就拉开了。
5. **宽松解析对这个结论没有影响。** 计分用的是全项目统一的宽松解析（`code/make_lenient_final260.py`，11-28 方案一），与 `eval_final260_lenient_results_20261128.md` 同一规则。新回复全部是纯 JSON，没有需要修的格式，严格和宽松结果完全相同；唯一读不出的是自创的 `point` 类型，统一规则也不补救（它只认框和线）。原 260 题里 Qwen 的 2 题平铺坐标（MF0030、MF0052）宽松解析能读出来，但 IoU 都是 0，所以主表的 0.162 宽松后也不变。

## 怎么读这个结果

- 对论文：Qwen 的主表分数里有一部分是“弃答惩罚”。把 none 去掉能挽回 IoU 0.038，但即使全部作答，Qwen（0.200）仍只有闭源模型的一半左右，本地模型与闭源模型的差距主要不是弃答造成的。
- 这只对 Qwen 做了。闭源模型本来就没有答 none（Sol、Claude、Gemini 均为 0），Gemma 有 21 题 none，没有重跑。
- 75 题是按 Qwen 自己的回复挑出来的，不是随机子集，不能拿来和其他模型在同一子集上比较“去掉 none 的效果”。
