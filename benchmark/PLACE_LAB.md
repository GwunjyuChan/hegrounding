# 交互地名实验

从平台主页点击“地名实验”，或打开：

- 独立实验目录：http://127.0.0.1:8769/place-lab.html
- 主地图集目录：http://127.0.0.1:8767/place-lab.html

两个服务使用不同数据目录，不互相覆盖。建议本周的地图诊断继续在 8769 进行。

地名实验不再显示欧洲战场地图，也不依赖战争事件。左上角 HE 返回平台首页；
线上为 `/`，本地独立服务默认返回 8767。独立工作区根路径也直接显示地名实验。
地图列表只包含用户上传的独立实验地图，以及已有地名任务的历史地图；旧标注和模型结果保留。
更改服务端口时可用 `--event-workspace-port` 和 `--place-workspace-port` 配置导航目标，默认 8767/8769。

## 操作

1. 点击“上传实验地图”，填写名称，选择图像或 PDF 及页码，上传后直接开始标注。
   也可以从“实验地图”列表打开已有实验。上传新图创建独立实验，不覆盖另一张图的标注。
2. 输入地名，点击“新增地名”。同一底图上重复输入完全相同的名字会打开已有实验。
3. 选择图钉标出文字中心，或用区域工具依次点击文字框的顶点。支持撤销、重做、清空与重新标注。
4. 填审核状态、置信度、备注，保存人工答案。点真值可以设置容差；区域真值按区域边界比较。
5. 重复新增和保存多个地名。界面只负责标注与查看，不再提供逐条运行按钮。
6. 在终端统一运行下面的批量命令，或标注完成后让 Codex 执行。
7. 完成后所有蓝色预测点自动叠加；红色是所有人工答案。可分别关闭图层、切换整批历史预测或导出整张地图的 JSON。

## 批量运行

### 网站标注、本地推理

线上入口：https://experiment.chanlukaka.com/labels/place-lab.html 。服务器没有部署 Qwen 权重，
不会在网页上提供不可用的逐条运行按钮。标注完多个地名后，点击“导出预测输入包”，在本地执行：

```bash
.venv/bin/python benchmark/run_atlas_vlm.py \
  --input /完整下载路径/place-input.zip \
  --backend qwen-local --model Qwen/Qwen3-VL-8B-Instruct \
  --limit 10000 --execute --output /完整输出路径/place-predictions.json
```

`--limit 10000` 表示最多处理包内 10000 条，不会生成额外任务；默认省略时只跑 1 条。
完成后在同一地图的“模型结果 JSON”选择结果文件，点击“导入预测结果”。
系统校验底图版本、任务 ID 和像素坐标，并新增批次，显示模型名和人工/模型对比。
此输入包明确要求原图像素坐标，与下面本地服务批量命令默认的相对坐标不同，不可混用。

### 本地标注与推理

在项目根目录执行：

```bash
# 预览将要运行的地名，不加载模型。
.venv/bin/python benchmark/run_place_batch.py

# 一次运行当前底图的所有已保存地名。
.venv/bin/python benchmark/run_place_batch.py --execute
```

默认连接 8769 的实验服务，使用 0–1000 相对坐标。可用 `--port` 指定其他端口，
多张地图时加 `--map-id`；也支持 `--coordinate-mode pixels`。
服务须保持运行。模型只加载一次，各地名使用独立请求、无共享对话历史；并非将所有地名放进一次模型生成。
每个地名发生解析错误时保留失败记录，并继续下一个；模型加载失败等整批故障另行报告。
中断终端等待不会取消服务端任务。

批次在提交时冻结名单与干净底图，只选择已保存过人工答案的地名（含有歧义、无法定位）；
仅新增但未保存答案的地名不进入批次。提交后新增的地名需下一次运行。
每次重跑新增一整个批次，不覆盖过去的结果。默认显示最新一批：不把旧批次的点混入本批，
未参与本批的地名显示“未预测”。鼠标悬停标记可查看地名，点选列表可查看单题详情。
页面每三秒同步结果，保留正在编辑但未保存的人工草稿；默认仍显示最后一个有结果的批次，直到新批次完成。

本版任务明确为**地名文字中心定位**，不是村庄中心、事件发生点或整片行政区域。
人工区域应围住地名文字本身。无几何的“无法定位”答案可以参与预测，但不计算位置误差。
模型预测显示前最好先完成独立人工标注，避免影响标注判断。

## 数据与隔离

已完成批次可离线导出人工/模型对比图、完整 JSON 和 Markdown 记录：

```bash
.venv/bin/python benchmark/export_place_results.py <完整批次目录>
```

结果保存到该批次的 `review/`，不覆盖已有导出、不重新运行模型。
人工标注取本批开始前的最后一次保存，避免把后续修改混入历史结果；原始输入拼写不做修正。

每个服务的 data-root 下单独保存：

```text
benchmark/atlas/place_lab/
  maps.jsonl           独立上传地图登记，不含战争事件
  tasks.jsonl          地名与底图版本
  gold.jsonl           人工答案追加历史
  predictions.jsonl    模型预测历史
  runs/<job_id>/
    input.json          实际任务与运行参数，不含人工答案
    map.png             运行时冻结的干净底图
    state.json          后台任务状态
    result.json         原始模型回答、解析结果、用量和预处理尺寸
    responses.jsonl     每个已完成地名的原始结果检查点
    progress.json       已处理数 / 总数
    worker.log          本地进程日志
```

不会修改原来的 Z0001–Z0010 或 P001–P008 记录。
新上传地图独立于战役地图。历史实验仍使用原来的底图版本；所有旧版标注保留，
但不会自动缩放迁移到新版本。恢复旧底图时，该版本的地名实验重新出现。
如果预测期间更换了底图，结果只保存到提交任务时的旧版本，不叠加到新图。

只把**干净底图、地名问题和坐标提示**交给模型。人工点/区域、备注、置信度、原事件文本和已有预测均不进入输入。
输出相对坐标按 x/1000×宽、y/1000×高换算。单点 [x,y] 可明确转换成 [[x,y]] 并记录转换标志；
不猜测坐标制式、不裁掉越界坐标、不因解析失败而伪造一个点。

## 模型与运行状态

本地批量命令固定使用缓存 `Qwen/Qwen3-VL-8B-Instruct`，不读取 API key、不访问付费 API、不下载模型。
网站导入的预测则显示结果文件中的实际模型名称，各导入批次分开保存。
每批预测启动独立进程并只加载一次模型，整批完成后释放模型内存。所有本地地名实验服务共享运行锁，
同一时间只允许一个此类推理任务。整批超时预算为地名数量乘以 10 分钟，超时终止整批，保留已完成响应与日志。
页面刷新后自动同步运行状态。服务重启后的未完成任务显示“中断”，可重新提交。
失败、拒答与成功定位分别显示；重跑新增记录，不覆盖以前的输出。

人工点显示原图像素距离与容差内/外；人工区域显示预测点是否落在区域内及到区域的距离。
这些是单题诊断，不是整个 benchmark 的准确率；图像比例尺改变后不能直接比较像素误差。
