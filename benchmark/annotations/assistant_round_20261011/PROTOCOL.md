# 第一轮 AI 辅助候选标注

日期：2026-10-11。标注者：本次 Codex 会话。性质：人工审核前的候选，不是 gold。

## 范围和版本

- 活动事件来自 `benchmark/zurich_pilot_10.jsonl` 与 `benchmark/map_first_candidates.jsonl`，不含 archive 或历史重复版本。
- 苏黎世第二次战役使用实验底图 `2ae3fca4eb15dced41f82401`，1538×1754；同时查看原参考图。当前 UI 的 1144×820 裁切不是本轮坐标系。
- 其余事件在各自原始参考地图上标注。这些地图有作战部署符号，因此本轮结果不是干净底图上的模型测试标签。
- 所有坐标为实际图像像素，左上原点，x 向右、y 向下。人工选取顶点，不按旧 gold 或模型坐标自动生成。
- 目视核对用的网格图和局部放大图仅为辅助；源图不改写，不进行 AI 补图或地物重建。
- 保留源文件、已有 gold、maps、预测及旧实验。输出只写本目录，不推送线上平台，不自动导入正式标注层。

## 状态

| 状态 | 含义 |
| --- | --- |
| proposed | 地物与问题有足够对应，给出待人工确认的候选几何 |
| ambiguous | 有多个可能位置、范围不足或无法确定边界；可附一个明确标为假设的几何，也可为空 |
| outside_map | 目标明确不在这一版本的图内；几何为空 |
| source_conflict | 问题、转述、地图或部队/时间关系有实质冲突；不强行画图 |
| unreadable | 图上文字或对应符号无法可靠判读；几何为空 |

所有状态的 `human_review` 均为 `pending`，`eligible_for_scoring` 均为 false。缺几何不等于模型拒答，更不等于该历史事件不存在。

## 置信度

这里的 1–5 是标注者对空间对应的定性自评，不是校准概率，也不代替史料真实性评价。

- 1：关键地物或对应关系无法确定。
- 2：只支持有条件的空间假设或粗略候选。
- 3：区域或线段对应较清楚，但边界、阶段、拼写或来源仍需复核。
- 4：目标和图上局部对应清晰；仍待人工审核。
- 5：保留给有独立交叉核验、边界明确且经审核的记录，本轮不用。

## 几何原则

- `feature_type` 使用项目既有 `FEATURE_TYPES` v1 词表。`target_kind` 单独保存部队区域、营地、行军等更细的目标类别；词表未覆盖的军事对象用 `other`，不擅自扩充平台词表。
- 区分实体、动作、时刻；驻地、出发点、渡河落点、推进路线、撤退终点不可互换。
- 命名村庄用可见建成区的近似多边形；不以印刷文字外框当作村庄。
- 路线只画有依据的可见部分；不添加任意起终点，也不将相邻城镇直连。
- 部队区域是本图所示部署的近似覆盖，不是考证过的真实战场边界。道路、地形区域与单位符号的空间定位依据分别说明。
- 区域范围不足时不使用覆盖半幅地图的大多边形。问题明确要求精确营地但材料只给村名时，记录粒度不足。
- 点/线评分容差暂置 null。未制定统一度量前，不靠调整容差让候选变成正确答案。

## 来源和偏差

- 逐条保留 `source_kind`、文本性质、来源链接与章节，地图推导样本不能算作独立文本验证。
- `source_check` 区分已看本地原文/在线原文/地图图注与仅核对现有候选转述，不能以候选自称的出处代替本轮核验。
- 苏黎世历史预测和旧标签已经出现在此前讨论中，记录 `prior_prediction_exposure: true`。本轮不读预测文件复制坐标，但不能声称苏黎世是盲标。
- 其余样本也属于本次 AI 辅助构建数据，不宣称完全独立的人工金标准。
- 文献许可及地图再分发权未因本轮标注而解决。

## 人工复核

先处理 `source_conflict`、`unreadable` 和 `ambiguous`，再逐图确认 `proposed`。审核应查看原图、文本与来源，不只看叠加图。确认后另建人工审核版本；不要直接把本文件改名为 gold，也不要跨底图版本迁移坐标。

## 输出格式

`decisions.json` 是本轮决策源文件；`build.py` 合并只读源事件并生成 `annotations.jsonl`、`manifest.json`、`REPORT.md`、26 张 `overviews/*.png` 和独立 `review.html`。HTML 内嵌原图原始字节，仅显示时缩放，未降采样。

这是独立的候选审核格式，不是现有 atlas gold 的可直接覆盖文件。导入前必须完成底图版本对齐、人工裁决和平台字段转换。`feature_type` 与平台词表兼容不代表整条记录可直接导入。

## 保存人工审核

通过本机 [审核工作台](http://127.0.0.1:8771/review.html) 操作，直接打开 `file://` 的 HTML 仍是只读模式。

右侧题目下方的 Human review 区域可选择接受、修改后接受、需修改、待补证据、剔除，填写审核者及备注，再点 Save。修改后接受、需修改、待补证据、剔除必须填写理由。没有几何的候选不能直接接受，但可以补画后选择“修改后接受”；有歧义的原候选若接受，需说明疑点如何解决。“需修改”仍可用于登记任务，直接改图请使用地图编辑工具。

每次保存追加一条到本目录 `human_reviews.jsonl`，包含审核者、时间、版本、候选指纹和底图指纹。返回原事件可修改审核意见，旧意见仍保留。候选或另一标签页的审核已变化时，拒绝静默覆盖。

### 直接编辑几何（2026-10-14）

- 在 Annotation map 模式选择箭头工具，拖动白色顶点；点击边线可插入顶点，选中顶点后用减号删除。点也可直接拖动。
- 点、线、多边形工具用于重新绘制。线和区域依次点击顶点后按对勾完成；原来没有几何的事件也可补画。
- 支持撤销、重做、清空及恢复原始 AI 候选。恢复原始候选只是更改草稿，不删除旧人工修订。
- AI 层保留原始候选，Human 层显示修订；两层可独立显隐。Reference 模式只查看参考图，不接受编辑，避免混用坐标。
- 修改完成后选择“Modified & accepted / 修改后接受”，填写审核依据和审核者，点 Save。原样接受使用 Accept。
- 人工几何保存在审核日志的 `human_geometry` 字段，坐标系为原始标注底图像素；`geometry_source` 区分 `human_edit` 与 `ai_candidate`。旧日志继续兼容，原始 `annotations.jsonl`、`decisions.json` 及底图不变。
- 保存校验几何类型、顶点数量、有限数值、图幅边界、重复顶点和区域自交；无效几何不落盘。多标签页旧版本保存会提示冲突，不覆盖较新的修改。
- 草稿在当前标签页内切换事件或刷新后保留；撤销记录仅在当前页面会话有效。关闭页面前仍应保存。审核通过仍不自动成为正式 gold，也不自动同步线上。
- 只更新网页时运行 `build.py --review-only`，不重新生成候选或重写审核日志。

未保存草稿只在当前标签页暂存，看到“已保存到本地文件”才表示正式落盘。接受也不自动转为 gold 或开启评分。AI 候选源文件、旧人工 gold 和线上网站均不改写。

服务未启动时，从项目根目录运行：

```sh
.venv/bin/python benchmark/annotations/assistant_round_20261011/serve_reviews.py --port 8771
```

服务仅绑定 `127.0.0.1`。导出的 `review.html` 不包含审核意见；意见由本地接口读取。重新运行 `build.py` 不删除或重写人工审核记录。
