# 事件标注与底图编辑

另有：[交互地名实验](PLACE_LAB.md)。从主页“地名实验”进入，可自定义地名、保存人工标注、
查看批量运行后的模型预测。

本周新增：[地名定位诊断与置信度标注](PLACE_DIAGNOSTICS.md)。人工标注可选 1–5 置信度；
旧记录默认未审核，模型输入不包含置信度或人工答案。

## 启动

在项目根目录执行：

```bash
bash benchmark/run_annotation_gui.sh --port 8767
```

打开 <http://127.0.0.1:8767/>，选择战役后进入统一的事件标注工作区。
底图编辑是当前任务内的操作，不再作为并列导航入口。旧 `/atlas.html?map=...` 链接仍可使用。
不要关闭正在使用的旧端口或同时用多个服务编辑同一个数据目录。

## 三层数据

| 数据 | 用途 | 是否交给 VLM |
| --- | --- | --- |
| 参考地图 | 原始作战部署图，用于交叉验证，也可显式选作底图 | 仅当用户选作底图 |
| 标注底图 | 已选参考图或上传图的固定裁切 PNG，不烘焙人工/预测图层 | 是 |
| 人工标注 | 对应某底图版本的事件几何、状态和证据 | 否 |

“空白”指没有事件答案，不是去掉地名、道路和河流的白纸。软件不保证导入图本身没有答案泄漏，仍需人工检查。
同一参考图片路径下的多个事件共用一个地图集；每个地图集只有一个当前底图，可保留多个历史版本。
当前从两份候选 JSONL 自动加载 26 张参考图及其 110 条事件：苏黎世 10 条与 Maps 候选 100 条。
新增图先用于审核，未自动生成干净底图或 gold。国家缺口与证据层级见 `COUNTRY_COVERAGE.md`、`MAP_EXPANSION_REVIEW.md`。
旧三图及其 20 条已归档，新增三张部署参考图尚未设置干净底图；见 [资料清单](MAP_FIRST_CANDIDATES.md)。
新增图现为布萨科、Marengo 和圣塞巴斯蒂安；Wkra 合图因辨识度问题已归档。布萨科以同图版的较高清扫描替换 Maps 小图，来源均保留。
苏黎世从 5 条扩展到 10 条，
新入口为 `benchmark/zurich_pilot_10.jsonl`；Z0001–Z0005 原记录、底图版本和标注均保持不变。
Z0006–Z0010 为待审核候选，不自动继承人工答案或模型预测。新增问题见 [苏黎世说明](ZURICH_ANNOTATION.md)。
新增参考图/事件仍需加入候选 JSONL，并使用现有 `battle_id`；本版不提供事件文本编辑或新的战役管理。

## 工作流程

1. 从主页选择战役。尚未选图时默认预览参考图，点击“使用当前参考图并开始标注”可直接确认；仅打开页面不会创建底图版本。已有底图的任务直接进入标注，不重置历史选择。
2. 需要替换或裁切时，点击任务顶部“编辑底图”，选择当前参考图、已导入图像，或上传 PDF/PNG/JPEG/TIFF/WebP/GIF。取消返回原任务；已导入原件仍保留，但不激活草稿。
3. PDF 页码包含说明页。当前 Usteri PDF 的第二幅地图是第 3 页。每次导入一页，可重复导入其他页。
4. 选择裁切工具拖出矩形，或填写像素边界。可旋转 90/180/270 度并设置长边上限，处理顺序为裁切、旋转、等比例缩小，不放大。
5. 点击“确认底图并开始标注”后绘制点、线、区域，填写证据并保存。“对照参考图”可打开旁边的参考图，顶部“编辑底图”可随时返回编辑。
6. 取消“人工标注”勾选可隐藏人工图层。下载的底图不包含人工/预测图层，但原始图像已有的作战符号不会自动去除。
7. 保存为 `outside_map` 的事件必须没有几何；导出 VLM 输入包只包含当前底图下的 `accepted` 事件。
8. “VLM 输入包”包含 `map.png`、`tasks.jsonl`、`prompt.txt`、`manifest.json`。只含所选底图，不额外附参考图，也不含人工证据、要素建议或答案。新版本记录 `base_map_role`：`reference_map` 或 `uploaded_map`；历史未标记版本为 `unspecified`。上传图也需人工检查泄漏风险。
9. “人工答案”单独导出 JSON；“人工结果图”将当前事件的已保存标记绘制到一份临时 PNG，不覆盖底图。

当前已导入 Usteri 1816 年 PDF 第 3 页，并初始化苏黎世市区及近郊的局部裁切。
这是可调整的初始版本，不是已通过审核的 1799 年底图。未替用户标注任何事件；Dietikon、Regensdorf 等范围外目标需自行审核。

## 版本和坐标

- 坐标统一为最终标注底图像素：左上为原点，x 向右、y 向下。不是浏览器显示像素，也不是参考作战图坐标。
- 导入 PDF 使用 Poppler，单页渲染长边 6000 px。它是固定渲染尺寸，不代表原扫描分辨率或地图测绘精度。
- 底图版本绑定来源、裁切框、旋转、输出尺寸及 PNG 的 SHA-256。保存新的图像配置不会迁移旧像素标注。
- 恢复旧底图版本会恢复该版本下已有标注。相同配置和图像的版本可复用；仅改来源备注不会使坐标失效。
- 人工标注和预测都是追加记录。人工标注取同一地图版本/事件的最新记录；预测取同一地图版本/事件/模型的最新记录，不同模型不会互相覆盖。保存时检查版本冲突。
- 原 `napoleon_annotations.jsonl`、`zurich_annotations.jsonl` 不受新工具影响。旧导出器不读取地图集数据。
- 底图编辑仅支持单页裁切和直角旋转；不进行跨页拼接、自动地理配准或生成式图像补全。

## 调用 VLM

本地 Qwen 的 [两阶段定位对比工作流](QWEN_STAGED_README.md) 支持先生成文字地点答案、
再输入底图定位，并与直接输入原文和底图的路线比较；人工真值仅在独立评分步骤使用。

导出 ZIP 后，先无成本校验（不读取 API key、不调用模型）：

```bash
.venv/bin/python benchmark/run_atlas_vlm.py --input /完整路径/vlm-input.zip
```

正式执行需显式选择模型并加 `--execute`。以下沿用项目此前使用的模型名作为示例，不是可用性承诺：

```bash
.venv/bin/python benchmark/run_atlas_vlm.py \
  --input /完整路径/vlm-input.zip \
  --model gpt-5 --limit 1 --execute \
  --output benchmark/atlas/runs/zurich_run01.json
```

使用项目根目录 `.env` 的 `OPENAI_API_KEY`。默认 Responses API；开源视觉模型的兼容服务可使用
`--api chat --base-url http://127.0.0.1:8000/v1 --model 实际模型ID`。模型必须支持图像输入及对应 API。
调用格式参考 [OpenAI 官方视觉输入说明](https://developers.openai.com/api/docs/guides/images-vision)。
运行时只有所选底图、段落、问题与坐标约定发送到指定服务，默认一次只跑 1 条、不自动重试。
预测和原始响应审计文件分别输出，失败/解析错误不算作成功拒答；文件已存在则拒绝覆盖。
这版提供推理及图像结果，不把旧米级定位指标用于新图，也尚未提供点线面综合评分。

### 本地 Qwen3-VL（离线）

需要严格保留导出底图的原始像素时，可为 `qwen-local` 增加 `--preserve-image-pixels`。
该选项关闭处理器 resize，仅在右侧/底部补白到 patch 对齐尺寸；原图像素与坐标原点不变，
预测仍须落在原图有效范围内。日志记录补白、实际尺寸和像素哈希；超过处理器像素预算时拒绝运行，
不会暗中缩小。默认行为未改变。注意它不能恢复 PDF 导入或既往底图导出时已经丢失的细节。

若本机已有 Transformers 模型缓存，可直接运行，不必启动模型 API 服务：

```bash
.venv/bin/python benchmark/run_atlas_vlm.py \
  --input /完整路径/vlm-input.zip \
  --backend qwen-local --model Qwen/Qwen3-VL-8B-Instruct \
  --limit 5 --max-output-tokens 4096 --execute \
  --output benchmark/atlas/runs/qwen_run01.json
```

本地后端不读取 `.env` 或 API key，关闭 Hub 联网与遥测，只使用缓存权重；缺少必要文件会报错，不自动下载。
自动选择 CUDA、Apple MPS 或 CPU，使用确定性 greedy 解码。记录设备、精度、缓存版本路径、依赖版本、图像 grid、token 数及每条耗时。
输入包、任务文字、像素坐标约定和解析校验与 API 后端共用；模型各自的视觉预处理不同，不代表内部图像表示完全一致。
`--model` 也可使用完整的本地模型目录。`--execute` 在这里表示实际执行本地推理，不表示调用付费服务。

## 导入预测

另有 [文本地点问答评估](TEXT_LOCATION_README.md)：不给地图、不输出坐标，比较模型对事件地点的文字回答并人工审核。
文字问答结果独立保存，不导入本页的几何预测图层。

运行脚本产生的 JSON 可直接在“模型预测 JSON”中导入。其他模型按此格式输出：

```json
{
  "map_version": "从输入包 manifest.json 复制的完整版本号",
  "model": "实际模型标识",
  "predictions": [
    {"event_id": "Z0004", "geometry": {"type": "point", "coordinates": [[123, 456]]}}
  ]
}
```

此处数值只是格式示例，不是事件真值。允许 `geometry: null` 表示模型拒答。
导入会检查地图版本、事件 ID 和几何边界，错误整批拒绝。
红色为人工标注，蓝色为 GPT-5，绿色为 Qwen，其他模型使用紫色并显示完整名称。
底图下方按模型分别勾选图层，可以单独查看或同时对照；悬停预测几何可看到模型名。
没有该事件记录时显示“无结果”，模型输出空几何时显示“拒答”，不与人工审核状态混淆。

在“结果图模型”下拉框选择模型，再点“模型结果图”，导出该模型的预测叠加 PNG。
图片含事件 ID、模型名称，文件名和 PNG 元数据也记录模型；底图和人工答案保持不变。
同模型重复实验目前显示该事件的最新记录，历史记录仍保留，但本版尚无同模型运行批次选择。

## 本地文件

```text
benchmark/atlas/
  originals/          导入文件原件，以内容哈希命名
  assets/             导入页 PNG 和干净裁切 PNG
  sources.jsonl       导入页来源、PDF 页码、尺寸和哈希
  maps.jsonl          各参考图的底图版本历史
  gold.jsonl          人工标注追加历史
  predictions.jsonl   模型预测追加历史
  runs/               可选模型运行结果及原始响应
```

以上都是研究数据，备份时应连同候选文件一起保存。UI 不提供删除原件或历史记录。
服务仅监听 `127.0.0.1`，导入上限 80 MB，PDF 渲染超时 90 秒；不开放任意本地文件路径。

## 服务重启后的保存

旧版页面可能在服务重启后提示 `Unauthorized local request`，因为页面仍持有上一进程的 CSRF 令牌。
新版在每次保存、恢复版本、导入预测和上传前获取最新令牌，不重新加载编辑器或丢弃草稿；
若服务恰好在请求之间重启，仅针对写入前的令牌拒绝重试一次，不重试标注版本冲突或不确定的网络错误。
安全校验仍然保留。更新前已经打开的页面需重新加载才能使用新代码，有未保存修改时不要直接刷新或关闭旧页。
